Commands (project root): `npm test` (vitest unit), `npx tsc --noEmit` (src+test), `npm run build` (tsconfig.build.json -> dist/), `npm run test:e2e` (builds, spawns dist/cli.js with HOME/COLUMNS set), `node dist/cli.js --by agent` / `--by task [--top N]`. No ESLint, no runner agent. Git: never `git add .`; add explicit paths so `.claude/settings.local.json` (plaintext key, gitignored) stays out; check `git diff --cached --name-only` before each commit.

Layout: src/{cli,run,transcripts,usage,version,diagnostics,reportAgent,reportTask,table,pricing,reconcile,sessionLabel}.ts; vitest.config.ts pins TZ=Asia/Kolkata (unit tests) and e2e spawn env sets the same; `run(argv,{home,cwd,width?})` returns `{code,stdout,stderr}` and is what unit tests call. test/helpers/{fixture,table,snapshot}.ts build SYNTHETIC JSONL / parse rows / snapshot the fixture root. Tests: test/unit/{run,task,cost,pricing,table,forbiddenImports}.test.ts; test/helpers/prices.ts has pinned TEST_PRICES (distinct rate per field, haiku over100k) passed as run()'s env.prices. NodeNext ESM, relative imports need `.js`.

Data gotchas (verified on real files, 2026-10-19):
- usage.iterations[type=message] sum == top-level usage; do NOT add them. advisor_message items (own model) are NOT in top-level; they feed the `advisor` row. 40 of 113 groups have no iterations at all.
- Dedupe: one Map per session, lead file ingested first, then subagent files, plain Map.set => keep-last and subagent-wins. Key `${message.id}|${requestId ?? uuid}`.
- Project dir name = cwd with every non-alphanumeric char -> "-". On macOS tmp dirs are symlinks: use fs.realpathSync for e2e cwd.
- Terminal width: cli.ts passes terminalWidth(stdout.columns, env.COLUMNS) (table.ts, default 80) as run's `width`; only --by task uses it. renderTable(header, rows, fit?) shrinks listed columns (agent to 6, then description to 8) with an ellipsis, counting code points. On real data the 7 non-text columns need ~64 chars, so at 80 the description gets ~10 chars; below ~78 columns the table overflows by design (floors).
- Task identity: ApiRequest.task = {id (session id for lead, `<session>/agent-<id>` for subagents), isLead, description}; meta.json description is free text and is only printed by --by task, through table.ts printable() (control chars, bidi overrides, whitespace -> one space). --by agent still prints agentType unsanitised (pre-existing).
- --by task TOTAL covers ALL rows even with --top; the "+K more, unpriced (included in TOTAL)" line is printed after the table. Token sum invariant task==agent holds on real data; Requests differs by the advisor iteration count.
- Pricing (S3): each deduped request carries ModelUsage (usage + model + cache 5m/1h split) for the message and for every advisor_message iteration (its own model). Rows stay keyed by agent/task; each row accumulates a Cost {usd, pricedCalls, unpricedCalls} per call, no per-model buckets. TOTAL cost = totalCost(requests) in request order, shared by both views, so the strings are identical. run() without env.prices treats every model as unpriced; cli.ts passes loadPrices() (prices.json via new URL("../prices.json", import.meta.url), valid from src/ and dist/). Haiku-only `over100k` block applies when input+cacheRead+cacheWrite of that call > 100000. Cache writes: 1h and 5m tiers clamped to the recorded total, remainder at 5m, warning counts calls where 5m+1h != total.
- Reconcile (cost-state lines exist only in lead files; totalCostUSD top-level; last line wins; <=0 or non-number = skipped). Printed in --by agent only. Any unpriced call anywhere => "Coverage: n/a (prices unverified)". On real data the opus rates reproduce cost-state costUSD exactly (rates verified), but cost-state records more sonnet/haiku/opus tokens than the transcripts hold (estimate ~40-50% under on two sessions); all 30 jsonl files under the project dir are read, so the cause of the token gap is unverified. loadProject only creates a session when it read a transcript file (memory/ is not a session).
- Rendered cost is `$` + toFixed(2); a row with any unpriced call shows "unpriced"; any unpriced row switches sort+Share to tokens.
- Tooling gotcha: writing `\uXXXX` escapes for U+2028/2029 through a shell heredoc turned them into literal characters and broke the regex; write them as `\u{2028}` (u-flag) or via python. Check with `grep -nP '[^\x00-\x7f]' src/*.ts`.
- Do not use the word f-e-t-c-h anywhere in src/ (forbiddenImports regex is \bfetch\b and matches comments).
- Streaming snapshots (verified 2026-10-19): Claude Code writes one transcript line per content block, all with the same message.id, so the kept (last) line holds only the last block and its stop_reason/usage. Lead responses end finalized (stop_reason set); most subagent kept lines have stop_reason null with a partial output_tokens, so subagent output and advisor rows are floors. ApiRequest.finalized (stop_reason is a string) feeds diagnostics.unfinalizedLines, printed in both views. An advisor server_tool_use block check on the kept line alone is WRONG (blocks sit on earlier lines; e.g. 9 blocks across lines vs 1 on kept lines); a correct count needs per-key block ids across all lines. BUILT in round 2 (criterion 1.9): advisor block = content item {type:"server_tool_use", name:"advisor", id:string}; ingestFile unions ids into ApiRequest.advisorCallIds on each map.set (also across lead+subagent files), diagnostics.advisorWithoutUsageLines sums max(0, ids - kept advisor_message count), printed verbatim (no "Warning:" prefix) in both views. Real project: 25 distinct ids, 11 records, K=14 (matches independent probe); no advisor-block line was zero-token or malformed.
- Test fixture assistantLine defaults stop_reason to "end_turn"; use stopReason: null / noStopReason: true for unfinalized. Tests of unrounded cost sums use rowsByAgent/rowsByTask (both exported) over loadProject(...).requests.
- S4.1 lead labels (2026-10-19): ingestFile returns LeadFacts {recordedCostUSD,title,startedAt,gitBranch} (lead file only; last ai-title wins, first valid ISO timestamp, first non-empty gitBranch, read before the non-assistant skip). sessionLabel(session) = "<title> (id8)" | "<local YYYY-MM-DD HH:MM> . <branch> (id8)" | bare id8; cutSessionLabel(label,width) keeps " (id8)" and cuts the head with an ellipsis only when >= 8 head chars fit, else bare id8. renderTable FitOptions.cut(rowIndex, width) is keyed by row index (header excluded), so only lead rows use it. With 1 lead row and tiny counts the 7 other columns take 68 chars, so column 0 = width - 68: bare id8 up to width 87, "Refactor... (id8)" from 88. At 80 columns lead rows look as before titles; titles show from ~88-100 columns. S4.2 (reconcile uses sessionLabel) is NOT built; run.test.ts canary asserts --by agent prints no title until then.
- Test gotcha: row(stdout, label) matches the first cell prefix, so a titled lead is found by its title, not by the id.
